- เซิร์ฟเวอร์ตรวจซ้ำก่อนผูกผล preview และก่อนบันทึก journal ไม่รับคอลัมน์คู่ความที่ไม่ได้จับคู่
- ไม่ใช่ข้อมูลนิรนาม เลขคดีและที่อยู่ยังต้องอยู่ภายใต้สิทธิ์เดิม
- วันที่ 15 พฤศจิกายน 2569 ลบชื่อย้อนหลังจากฐานใช้งานแล้ว เปลี่ยนรหัสหมายเป็น N1-SHA256 และเชื่อมรายการหน่วยเบิก/บัญชี/รอบ/รอตรวจ/Audit ไปยังรหัสใหม่ ชื่อผู้ส่งและข้อมูลการเงินคงเดิม มีสำรองก่อนแก้ไขแยกต่างหาก เปิดได้เฉพาะเจ้าของไฟล์ และยังมีชื่อเดิมสำหรับกู้คืน
- วันที่เก็บเป็น YYYY-MM-DD ค.ศ. รองรับเซลล์วันที่ Excel ระบบ 1900/1904 เลขไทย พ.ศ./ค.ศ. และชื่อเดือนภาษาไทย
- ข้อความวันที่ใช้วัน/เดือน/ปี ปี 4 หลัก เช่น 6/11/2569 หรือ ISO 2026-11-06 ปีไทยย่อ 69 รองรับ แต่ปีสั้นที่กำกวม เช่น 26 จะถูกปฏิเสธ ให้แก้ปีเป็น 4 หลักก่อนนำเข้า
- วันที่ผิดรวมถึงวันที่รับเงินที่มีค่าแต่แปลงไม่ได้ จะหยุดพร้อมแจ้งแถว ไม่ตัดทิ้งเงียบ ๆ

## สถานะและปีงบ

- หน้าตรวจเบิกจ่ายอ่านทั้งรหัสรอบบนหมายและรายการของรอบที่ยืนยัน เพื่อไม่แสดงพร้อมเบิกซ้ำ
- หมายฟรีก่อนเริ่มปีงบหรือพ้นปีงบโดยยังไม่เบิก แสดงไม่เบิกจ่าย ยอด 0 ในรายงาน พร้อมคงยอดอ้างอิงเดิม ไม่เขียนแก้ยอดรอบหรือสิทธิทางการเงินย้อนหลัง
- กฎนี้ยึดคำสั่งล่าสุดของผู้ดูแลระบบ เอกสารข้อกำหนดเดิมเรื่องติดตามรายการค้างข้ามปีไม่ได้ใช้อนุมัติเบิกข้ามปีอัตโนมัติ
- หมายมีเงินคงกฎเดิม การแบ่ง 60/40 และเศษคงเดิม
- ตัวกรองวันสิ้นสุดรวมเวลาทั้งวัน และสรุปรอบรองรับปีงบที่อ่านเป็นข้อความหรือตัวเลข

## การลบชื่อย้อนหลัง

- ตรวจอ่านค่ากลับทุกแถวของ NOTICES, LEDGER และ IMPORT_REVIEW ว่าช่องผู้รับ ผู้วางเงิน และคู่ความไม่มีชื่อที่อ่านได้
- เปลี่ยนรหัสหมายเป็น N1-SHA256 และตรวจอ้างอิง BUDGET_UNITS / PAYOUT_ITEMS / LEDGER ว่าไม่เกิดรายการหลุด
- รหัสเดิมอาจมีจุลภาคภายใน ต้องอ่านเต็มรหัสก่อนย้าย มิฉะนั้นอาจแยกรหัสผิดและตีความหน่วยล็อกไม่ถูกต้อง
- เปรียบเทียบผลคำนวณก่อน/หลังลบชื่อ และตรวจยอด สถานะ ยอดแบ่ง และเศษของรอบยืนยันว่าตรงเดิม
- ตรวจรายงานก่อนปิดงบและการนำเข้าไฟล์เดิมซ้ำ ผลตรวจจริงเก็บแยกในพื้นที่ของผู้ดูแล ไม่บันทึกข้อมูลหรือยอดจากฐานจริงใน repository
- PrivacyMigration.gs เป็นเครื่องมือเจ้าของโครงการ ไม่มี API route ตรวจสำรองและ hash ก่อนเขียน ล็อกระหว่างทำงาน และคืนค่าตารางเดิมหากเกิดข้อผิดพลาด
- การทดสอบข้อมูลจำลองครอบคลุมรหัสมีจุลภาค การเชื่อมรอบ/หน่วย/บัญชี/รอตรวจ การนำเข้าซ้ำ และการคืนข้อมูลเมื่อเขียนสะดุด

## กฎข้อมูลและเครื่องมือออฟไลน์ รุ่น 0.7.7

- ผู้รับเป็น R1 จาก shared formatter เดียวกัน ไม่ใช้ฐานะแทนรหัส ผู้วางเงินเว้นว่างตั้งแต่คำขอนำเข้าและหลังบ้าน ไม่อาศัยช่องนี้ตรวจประเภทหมายในโหมดตัดชื่อ แต่ยังตรวจราคา ประเภท พื้นที่ และข้อมูลซ้ำ
- การเปรียบเทียบรายการเก่าตัดค่าผู้วางเงินออกในหน่วยความจำ เพื่อไม่สร้างความเปลี่ยนแปลงเทียมจากการเปลี่ยนคำว่า มีผู้วางเงิน เป็นช่องว่าง ไม่แก้ข้อมูลเก่าทุกแถวอัตโนมัติ
- เครื่องมือ tools/party-cleaner/notice-pay-party-cleaner-offline.html ฝัง ZIP และ import-formats.js ใช้ได้เมื่อปิดเครือข่าย รองรับ .xlsx และไม่เปลี่ยนเลขคดีในไฟล์ คงหัวรายงาน ผู้ส่ง ยอดท้ายและรูปแบบเซลล์ รายละเอียดข้อจำกัดและการตรวจยอดดู tools/party-cleaner/README.md
- สถานะไฟล์สำรองที่ยังมีชื่อ: ยังไม่ได้ยืนยันการเก็บลงเครื่องในศาลหรือการลบถาวร ให้เจ้าของดาวน์โหลดลงพื้นที่ภายใน เปิดและตรวจทุกชีต จำนวน ยอดรายผู้ส่ง ยอดรวมและรอบยืนยันก่อน จากนั้นจึงลบเฉพาะสำรองที่ระบุและยืนยันลบถาวรจากถังขยะ ไม่ลบฐานใช้งานและไม่ล้างถังขยะทั้งบัญชี
- การดาวน์โหลดลงเครื่องมือบนคลาวด์ไม่ใช่การเก็บลงเครื่องในศาล ผลตรวจจริงและตำแหน่งสำรองไม่บันทึกลง repository
- ย้อนกลับโปรแกรมได้ด้วยหน้าเว็บ commit d98e61930761435bda00379758615200679004c2 และ Apps Script เวอร์ชัน 18 โดยคงฐานข้อมูลเดิม
