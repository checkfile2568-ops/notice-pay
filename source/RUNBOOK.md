- **ประวัติรอบเป็นหลัก:** หมายที่อยู่ในรายการของรอบ CONFIRMED แต่ช่อง NOTICES.payout_round_id ว่าง ทุกหน้า (สถิติ ทะเบียน ภาพรวม ค้นคดี รอบเบิก รายงานคงค้าง คำนวณ) อ่านรอบจากประวัติ (`roundLinks_` / `linkNotices_` ใน Payout.gs) ใช้ยอดเดิมในรอบแทนยอดอ้างอิง ไม่จัดเป็นรอตรวจ ไม่เสนอเบิกซ้ำ และไม่คำนวณทับ · ไม่เขียนช่องรอบในชีตเอง
- **สรุปค่าตอบแทน:** รอบที่ช่องสถานะจ่ายเงินจริงว่างแสดง "ยังไม่บันทึกหลักฐานจ่าย" (ไม่ได้แปลว่ายังไม่จ่าย) · การเงิน/ผู้ดูแลเลือกหลายรอบแล้วกด "บันทึกว่าจ่ายแล้ว" ได้ (API `round_payment_bulk` แบบ journal ใช้วันที่ของแต่ละรอบหรือวันที่ระบุ ไม่เปลี่ยนยอด/เศษ/รายการ)

## รุ่น 0.7.9 — เมนูตามงานและสรุปค่าตอบแทน

- ชื่อระบบ: ระบบบริหารจัดการค่าส่งคำคู่ความ
- เรียงเมนู สถิติ → นำเข้าไฟล์ → หมายเงินนอกงบประมาณ → หมายเงินงบประมาณ → ภาพรวม 2 ประเภท → การเงิน · ตรวจสอบก่อนเบิก → รอบเบิก 60/40 → สรุปค่าตอบแทนเจ้าพนักงาน → ตั้งค่าและข้อมูลอ้างอิง
- หน้าแรกจัดสถิติก่อนกล่องนำเข้าไฟล์ คงธีมเขียวเดิม รองรับมือถือ แท็บเล็ต และคอมพิวเตอร์
- ค้นรายหมายด้วยเลขคดี/เลขหมาย กรองพื้นที่ ผู้ส่งและสถานะได้ หน้ารวมสรุปยอดรายผู้ส่งและรายพื้นที่ แตะชื่อเพื่อกรองรายการ
- ค่าตอบแทนอ่านส่วน 60% จาก lines_json ของรอบ CONFIRMED โดยตรง แยกมีหลักฐานจ่ายจริงกับยังไม่มีหลักฐานจ่าย ไม่คำนวณแบ่งใหม่ ส่วน 40% เป็นยอดนำเข้ากองกลาง ไม่ใช่เงินรับรายบุคคล
- รายงานไม่รวมรอบยกเลิก ปีงบรับทั้งตัวเลขและข้อความ บัญชี COURIER เห็นเฉพาะยอดตนเอง บัญชี VIEWER เห็นสถิติรวมโดยไม่ได้รับรายละเอียดคดี
- หากข้อมูลแบ่งยอดของรอบเดิมอ่านไม่ได้ ให้ DATA_REVIEW เพื่อให้ตรวจรอบ ไม่แทนด้วยยอดศูนย์
- ยังคงรหัสรอบ ใบเสร็จ และหลักฐานเดิม เลขที่ใบเบิกแยกยังไม่ได้เพิ่มเป็นทะเบียนใหม่ ต้องตรวจจากเอกสารต้นทาง
- คงสูตรคำนวณอัตรา การจับคู่ R1/N1 สูตร 60/40 วิธีจัดเศษ และประวัติเดิม ไม่ยืนยันรอบหรือบันทึกจ่ายระหว่างตรวจรุ่น
- เครื่องมือตัดชื่อออฟไลน์ยังเป็นรุ่น 0.7.8 และใช้กฎเดิม
- ตรวจฐานจริงด้วย verify079ReadOnly: อ่านชีตซ้ำแล้วเทียบ hash ก่อน/หลัง ตรวจสมดุลสถานะและขอบเขตผู้ส่ง ไม่บันทึกข้อมูล
- เผยแพร่ Apps Script ก่อนหน้าเว็บ ใช้ deployment URL และสิทธิ์เดิม
- ตัวอย่างหน้าจอ source/preview/workflow-079.html ใช้ข้อมูลสมมติเท่านั้น ไม่มี API หรือ token

## การนำเข้า

- ใช้ไฟล์ Excel รูปแบบเดิม เลือกชนิด ISSUE / RESULT / PAY (30) / FREE18 ให้ตรงกับไฟล์ แล้วตรวจผลก่อนยืนยัน
- หน้าเว็บตัดชื่อโจทก์ จำเลย ผู้รับหมาย และชื่อผู้วางเงินออกจากคำขอนำเข้า ใช้รหัส SHA-256 ที่ผูกกับเลขคดีแทนชื่อผู้รับเพื่อป้องกันการรวมหมายต่างฉบับเข้าด้วยกัน
- เซิร์ฟเวอร์ตรวจซ้ำก่อนผูกผล preview และก่อนบันทึก journal ไม่รับคอลัมน์คู่ความที่ไม่ได้จับคู่
- ไม่ใช่ข้อมูลนิรนาม เลขคดีและที่อยู่ยังต้องอยู่ภายใต้สิทธิ์เดิม
- วันที่ 15 พฤศจิกายน 2569 ลบชื่อย้อนหลังจากฐานใช้งานแล้ว เปลี่ยนรหัสหมายเป็น N1-SHA256 และเชื่อมรายการหน่วยเบิก/บัญชี/รอบ/รอตรวจ/Audit ไปยังรหัสใหม่ ชื่อผู้ส่งและข้อมูลการเงินคงเดิม มีสำรองก่อนแก้ไขแยกต่างหาก เปิดได้เฉพาะเจ้าของไฟล์ และยังมีชื่อเดิมสำหรับกู้คืน
- วันที่เก็บเป็น YYYY-MM-DD ค.ศ. รองรับเซลล์วันที่ Excel ระบบ 1900/1904 เลขไทย พ.ศ./ค.ศ. และชื่อเดือนภาษาไทย
- ข้อความวันที่ใช้วัน/เดือน/ปี ปี 4 หลัก เช่น 6/11/2569 หรือ ISO 2026-11-06 ปีไทยย่อ 69 รองรับ แต่ปีสั้นที่กำกวม เช่น 26 จะถูกปฏิเสธ ให้แก้ปีเป็น 4 หลักก่อนนำเข้า
- วันที่ผิดรวมถึงวันที่รับเงินที่มีค่าแต่แปลงไม่ได้ จะหยุดพร้อมแจ้งแถว ไม่ตัดทิ้งเงียบ ๆ
